# 语义与计划字段

首次规划或修改全篇覆盖逻辑时使用；局部维护只读取相关部分。画面验收以项目 `AGENTS.md` 为准，数据格式以 [shot plan schema](../../../../schemas/broll-shot-plan.schema.json) 和 [visual lock schema](../../../../schemas/visual-lock.schema.json) 为准。

## 全篇理解与覆盖

完整理解 SRT 的主张、观众起点、逻辑骨架、情绪推进、回调物及需要真人建立信任的段落。候选区间应降低理解成本、演示操作、解释机制、形成对比、量化证据或制造必要感受；泛化氛围不能成为选择理由。

`rhetorical_coverage[]` 为章节、问题、分类和回调成员逐项记录 `member_id / label / role / required / covered_shot_ids`，每个必需成员指向至少一个存在的活动 Shot。“三个问题/三种类型”等同构系列须逐项公开，样板不能替代未展示成员。

每个单元只选一个主要 `visual_job`，例如操作演示、机制解释、抽象落地、对比、证据量化、感受或定位连接。次要效果可以并存，理解优先于装饰。

## 场景先于摄影

两类参考齐备并形成视觉锁后，才把候选区间写成具体场景；此前可以理解语义和选择区间。`scene_design` 包含：

| 字段 | 内容 |
| --- | --- |
| `subject` | 观众实际看见的主体 |
| `setting` | 具体空间 |
| `visual_progress` | 动作与结果，或标题、对照、卡片、图标、空间关系怎样推进信息 |
| `visual_style_application` | 主体、材质、空间怎样落实视觉锁 |
| `talking_head_transition` | 切入切出口播时的光色、密度、方向和节奏 |

`scene_and_reason` 说明画面为何对应此处口播，避免可任意套用的隐喻。实操段让 AI 界面状态跟随操作；概念段直接表达关系；比较时保持共同变量；数字可以通过清楚大字与尺度/结果成为证据。抽象观点无需强编动作故事。

人物可用积木、微缩玩偶、黏土、纸偶、插画等明确动画化角色；无必要时用工具、界面或物件。不得使用拟真人演员、拟真人操作员、AI 真人口型或擅自创造的用户/名人化身。

## 时间与镜头

节拍来自动作、对象、关系、条件、转折、数字、结论或情绪的新增信息。填充词与轻微重复可合并，不平均分秒。`source_start_seconds / source_end_seconds` 和 `source_range` 为原片绝对时间，`beats[].start_seconds / end_seconds / time` 为单元内相对时间；可见结果须留出识别时间。

| 字段 | 约束 |
| --- | --- |
| `spoken_addition` | 此刻口播新增的信息，只用于规划，不进入 H3 生成脚本 |
| `visual_content` | 当前可见动作/结果或信息关系的变化 |
| `shot_number` | 首节拍为 1；延续同镜头保持编号，新镜头只递增一位 |
| `framing` / `camera` | 景别、机位/角度、画面方向及运镜；固定也写明 |
| `shot_size / camera_angle / viewpoint` | 可比较的景别、角度和视点签名 |
| `transition_in` | 首节拍 `start`；同镜头 `continue`；切镜用 `cut / match_cut / occlusion_cut` |

新镜头应增加主体、空间、状态、关系、视点或时间信息。轻微位移留在镜头内；连续性可通过主体、道具、方向、形状、动作接力或声音保持。按语义选择硬切、匹配或遮挡转场，不为套用转场而改变内容。

语义 beat 数量不固定。阶段二将节拍装入 1–4 张故事板，每张严格四格，再从全部 Panel 选择 3–5 个差异明显的 H3 状态锚点；不将 beat、Panel 与锚点混为一谈。过多独立信息应在计划阶段简化或调整区间，不将已选单元拆成多条输出交给用户后拼。

## 文字策略

- `none`：不依赖文字。
- `keyword`：一个短关键词或极短大字。
- `concept_ui`：表达界面层级和状态，不将伪文字当准确内容。
- `exact_ai_text`：必须准确的中文、终端命令、对话或 UI 字段逐字指定，以文字为唯一焦点。

有文字时减少背景层级、人物、道具、粒子与并行动作；正面、巨大、高对比，并留稳定时间。避免小卡片、密集标签、斜视文字与多组中文争夺注意力。生成素材必须由 AI 生成，不能使用真实截图、录屏或后期覆盖文字。

## 产物

顶层记录 `schema_version: 3.0`、完整节目时长、覆盖目标、区间并集时长、实际覆盖率与 `rhetorical_coverage`。每单元按 schema 记录源范围/原话、主要视觉任务、场景与对应理由、风格、序列模式、节拍/转场、连续性、必要文字、声音意图和生成时长。

审阅 Markdown 与 JSON 对应，公开必需成员、入选区间、具体画面、切点及重要淘汰原因。核对是否真正对应当前口播、有清楚的信息推进；发现泛化隐喻或文字与画面脱节时，修订该场景。第一阶段不编写 Imagine prompt、H3 prompt 或估价。
