自分専用のクラウド環境に MiniMax H3 を導入し、試作、制作、振り返りを重ねながら、再現性のある参考画像、映像表現、生成のノウハウを蓄積。繰り返し活用できる自分のスタイルを育てます。

**AI 動画を継続的に制作し、実践を通じてスタイルを磨きたいクリエイター向けです。** 現在の主なワークフローは、トーク動画の SRT 字幕を独立した 4K B-roll 素材に変換するものです。Agent がショット設計、ストーリーボード、クラウドでの実行を担当します。

## 🎯 このプロジェクトを作る理由

一度の生成で得られるのは一本の動画です。自分の制作手法は、制作を続けることで蓄積されます。自分で借りたサーバーにモデルを導入すれば、同じ環境で被写体、質感、配色、光、ショットサイズ、動きを繰り返し試せます。うまくいった方法を残すことで、手当たり次第の試行錯誤を少しずつ減らします。

蓄積する資産は、主に次の三つです。

| 蓄積するもの | 次の制作にどう役立つか |
| --- | --- |
| **自分のビジュアルリファレンス** | キャラクター、質感、配色、光を安定させ、複数の動画でスタイルの一貫性を保ちます。 |
| **自分のショット設計とプロンプトの経験** | どのシーン、動き、ショットの組み合わせなら、狙った結果を得やすいかが分かります。 |
| **自分の制作・選別フロー** | ストーリーボードを確認してから動画を生成し、問題を記録して次の制作に改善を反映します。 |

目標は、出力を安定させ、使える素材が得られる割合を徐々に高めることです。**本プロジェクトに学習やファインチューニングは含まれません。生成回数を増やすだけで、モデルの重みが自動的に変わることはありません。** 改善につながるのは、あなたと Agent が蓄積する参考資料、絵コンテ、プロンプト、振り返りの経験です。

## 🎬 トーク原稿から独立した動画素材へ

![ショット設計、4コマのストーリーボード、クラウド生成の3段階フロー](docs/images/workflow-v2.png)

<p align="center"><sub>01 ショット設計 → 02 ストーリーボード確認 → 03 クラウドで生成・ダウンロード。上記2枚の紹介画像はいずれも AI が生成した概念図であり、H3 で実際に制作した動画の作例ではありません。</sub></p>

| 段階 | あなたと Agent が一緒に行うこと | 対応する Skill |
| --- | --- | --- |
| **01 · ショット設計** | SRT 全文、内容のスタイル参考、トーク映像とのつながりの参考を読み、画面の内容、挿入区間、撮影のリズムを決めます。 | [srt-broll-producer](.agents/skills/srt-broll-producer/SKILL.md) |
| **02 · ストーリーボード確認** | 各ボードは必ず4コマ。まず1〜2件のサンプルを確認してから全体を制作し、各ユニットにつき余分な表示のないアンカー画像を3〜5枚選びます。 | [broll-storyboard-producer](.agents/skills/broll-storyboard-producer/SKILL.md) |
| **03 · 生成と受け取り** | 確認済みのストーリーボードからリクエストを組み立て、AutoDL で生成、ダウンロード、中断タスクの再開を行い、最後に人が動画を確認します。 | [h3-video-runtime](.agents/skills/h3-video-runtime/SKILL.md) |

ビジュアル方針とショット計画、サンプル、全体の絵コンテは、それぞれユーザーが確認します。承認後に予算内で実行します。標準の納品物は、1本あたり **4〜15秒の独立した 4K 素材**です。トーク動画全体への自動編集は行いません。第2段階では、Codex ホストに搭載された `imagegen` の画像生成機能が必要です。

[3段階フローの詳細](docs/three-stage-workflow.md) · [インストール・運用ガイド](docs/getting-started.md)

## 💰 実際のコスト：GPU 利用料と継続ストレージ料

以下は、**著者が提供した制作時の実測経験と予算の目安です。記録日は2026年9月7日**。プラットフォームの最新の統一料金ではなく、すべてのタスクで同じコストになることを保証するものでもありません。金額はすべて中国人民元（CNY）です。

| 項目 | 著者の実測経験・現在の算定方法 | 予算を立てる際の考え方 |
| --- | --- | --- |
| **動画生成コスト** | 約 **CNY 0.10 / 秒** | 採用しなかった候補も含め、生成したすべての動画の合計時間で計算した経験値です。最終的に採用した素材の1秒あたりのコストは、これより高くなる場合があります。継続ストレージ料は別途必要です。 |
| **GPU サーバー** | 約 **CNY 6 / 時間** | サーバーを実際に占有した時間で計算します。初期設定、待機、再試行も起動時間に含まれます。 |
| **1回の制作例** | **20ショット、約2時間。著者の記録では約 CNY 10** | CNY 6 × 2時間で計算する予算は **約 CNY 12**。実測時の記述と時間単価による見積もりを分けて記録しています。 |
| **データの継続保存** | 約 **CNY 3 / 日**、30日で **CNY 90 / 月** | クラウド上にモデルとデータを保持する固定費として、月々の予算に別枠で計上します。 |

**データを1か月間保持し、上記の20ショットの制作を1回だけ行う場合、予算例は CNY 90 + CNY 12 ≈ CNY 102 です。** 記載のストレージ規模、30日間、GPU 利用2時間で計算した例であり、パッケージ料金ではありません。すべての費用を「1秒あたり CNY 0.10」に含めているわけでもありません。

総支出には、利用する画像生成サービス、Agent のサブスクリプション、その他の追加サービスの料金も考慮する必要があります。GPU を停止した後も、プラットフォーム上でストレージが保持され、課金が続いていないかを別途確認してください。生成を止めても、すべての費用がゼロになるとは限りません。請求の根拠がそろっていない場合、プログラムは実費を「要確認」のまま保持し、見積もりを支払い済みの請求額として扱いません。

## 🚀 始める前に用意するもの

- **手元の環境**：画像生成機能を内蔵した Codex、Python 3.11+、FFmpeg/FFprobe、OpenSSH。パスワードによる SSH 接続には `sshpass` も必要です。手元のパソコンに NVIDIA GPU は不要です。
- **クラウド環境**：現在の導入資料は AutoDL の RTX PRO 6000 Blackwell 96GB を対象としています。メモリは最低120 GiB、永続ディスクの空き容量は320 GBが必要です。8個のモデルは合計約156.45 GBです。
- **制作に使う入力**：トーク動画の SRT 全文、内容のスタイル参考、トーク映像とのつながりの参考、今回の生成予算。

リポジトリへのアクセス権を取得したら、手元のパソコンでクローンしてインストールします。

```bash
git clone https://github.com/erduo1998-cell/h3loom.git h3loom
cd h3loom
uv sync --frozen
source .venv/bin/activate
```

uv がない場合は、`python3 -m venv .venv` で環境を作成し、有効化した後に `python -m pip install -e .` を実行できます。Codex でクローンしたディレクトリを開き、Agent に `AGENTS.md` を読ませてください。3つの Skill はプロジェクトに同梱されているため、グローバル環境の Skill を上書きする必要はありません。

まずはテスト用字幕で入口を確認します。この操作では有料の生成は許可されません。

```bash
broll-video init --name "安装检查" --srt examples/demo.srt --ratio 16:9 --execution estimate_only
broll-video next <task-id>
```

`<task-id>` には、直前のコマンドで返されたタスク番号を指定します。本番制作の前に、[運用ガイド](docs/getting-started.md)に沿ってクラウドへの導入、ビジュアルの確認、今回の予算承認を済ませてください。新しい GPU への導入には実機での検証が必要です。任意のクラウド、GPU、画像生成バックエンドですぐに動作することを保証するものではありません。
